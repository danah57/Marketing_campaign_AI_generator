4.3 ML — Custom scikit-learn pipeline (ml/pipeline/)
Architecture
Two-stage stacked model:

Stage 1 — 5 targets × 3 quantiles (q10, q50, q90) = 15 regression models

Targets: clicks, impressions, conversion_rate, engagement_score, acquisition_cost
Stored as .pkl files in ml/artifacts/stage1/
Stage 2 — Uses Stage 1 q50 predictions as scaled features + campaign metadata

stage2_roi_model.pkl — predicts ROI (scaled, then inverse-transformed)
stage2_success_model.pkl — predicts success probability (predict_proba)
SHAP explainers: shap_explainer_roi.pkl, shap_explainer_success.pkl
Verdict thresholds (InferenceEngine.predict_one)
Verdict	Condition
LAUNCH	predicted_roi >= 6.5 AND success_probability >= 0.75
REVISE	predicted_roi >= 5.0 AND success_probability >= 0.50 (and not LAUNCH)
DROP	Otherwise
ML input schema (Stage 7 builds this from brief + context)
{
  "Channel_Used": str,           # e.g. "Instagram"
  "Campaign_Type": str,          # e.g. "Social Media"

6. Existing Recommendation and Insights Logic
6.1 Pipeline execution order
Stage 1 (save brief)
  → Stage 2 Business
  → Stage 3 Competitors
  → Stage 4 Audience
  → Stage 5 Strategy
  → Stage 6 Tactical
  → Stage 7b Influencer
  → Stage 7 ML Evaluation
  → Stage 8 Calendar
All stages run sequentially. Shared context dict accumulates each stage's output (also merged at top level via context.update(stage_output)).

Checkpoint resume: if checkpoints/{job_id}/stage_{N}.json exists and stage_failed is not true, stage is skipped (loaded from disk).

Real mode: Claude generates JSON with:

business_summary, swot (strengths/weaknesses/opportunities/threats)
brand_positioning, market_challenges, growth_opportunities, competitive_advantage
campaign_readiness_score (float), campaign_readiness_reasoning

6.3 Stage 3 — Competitor insights (stage3_competitors.py)
Pre-LLM rule engine: enrich_competitor() infers per-competitor:

Real mode Claude output:

competitor_summary, content_gaps[], positioning_opportunity
channels_to_prioritize[], topics_to_avoid[], competitor_weaknesses_to_exploit[]
Downstream use: channels_to_prioritize used in Stage 6, 7b, 7; positioning_opportunity in Stage 4.

6.6 Stage 6 — Tactical content recommendations (stage6_tactical.py)
Built-in virality rubric (in system prompt):

Rule	Score impact
Caption opens with question or bold statement	+2
Clear emotional hook	+2
Strong CTA	+1
Social proof or data	+1
Platform-native format	+1
Over character limit	−1
No hashtags (IG/TikTok)	−1
Real mode output: platform_content per channel with 2 variants (A/B), content_creation_checklist, campaign_hashtag_set

Channel selection logic: merges brief.current_channels + context.channels_to_prioritize, deduplicated; fallback ["Instagram", "Facebook"]

6.7 Stage 7b — Influencer recommendation (stage7b_influencer.py)
Candidate sourcing (priority order)
brief.influencer_candidates (from Node POST body)
load_influencer_candidates() → data/influencer_cache.json first, then PostgreSQL
If empty → skip stage (influencer_stage_skipped: true)
Rule-based scoring (compute_influencer_score)
Signal	Points
Platform in campaign channels	+2.0
Engagement rate	up to +3.0 (min(rate * 1.5, 3.0))
Followers	up to +2.0 (min(followers/200000, 2.0))
Category overlap with campaign	+1.5 per match
Audience age match	+1.5
Audience gender match	+1.0
Selection: select_top_influencers() — max 3 influencers with score ≥ 5.0

Claude role (real mode only): Generates strategy_note + per-id outreach_templates (not fit scores)

suggested_budget_usd: Hardcoded 0.0 in current code (not AI-calculated)

6.8 Stage 7 — ML campaign evaluation (stage7_evaluation.py)
Real mode flow:

Build campaign_input dict from brief + Stage 5 context
InferenceEngine.predict_one() → ROI, success probability, verdict
SHAP → plain-language drivers/detractors
Claude writes written_explanation paragraph
Fallbacks:

SKIP_ML_EVALUATION=true → mock
ML engine load failure → mock
ML prediction failure → mock
Claude explanation failure → mock text with real ML numbers preserved
Mock output: ml_score: 0.84, ml_verdict: "LAUNCH", predicted_roi: 7.6, static SHAP lists

Critical: These fields are not returned in GenerateResponse to Node.js.

6.9 Stage 8 — Calendar scheduling (stage8_calendar.py)
